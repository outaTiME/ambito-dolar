# AGENTS.md - Agent Guide for ambito-dolar

Guide for coding agents. Minimal targeted edits. Preserve behavior unless asked.

## Repository Layout

- Monorepo: Yarn workspaces + Lerna (`packages/*`).
- `packages/core` (`@ambito-dolar/core`): shared domain utils (rates, dates, formatting, fetch helpers). ESM (`"type": "module"`).
- `packages/client` (`@ambito-dolar/client`): Expo React Native app (iOS, Android, web).
- `packages/backend` (`@ambito-dolar/backend`): SST v4 backend (Lambda handlers). ESM (`"type": "module"`).
- `packages/website` (`@ambito-dolar/website`): Astro website (static landing).
- `packages/screenshots` (`@ambito-dolar/screenshots`): store screenshots, argent captures and a canvas compose, see `docs/store-screenshots.md`.

## Runtime and Tooling

- Node `22` (`.nvmrc`). Yarn `4.x` (root `packageManager`). Install: `yarn install`. Linker: `node-modules` (`.yarnrc.yml`).

### Native code

- **Both platforms are CNG**: `packages/client/android/` and `packages/client/ios/` are generated by
  `expo prebuild`, hand edits are lost. iOS widget extension source lives in
  `packages/client/targets/`. Details and post bump order in `packages/client/AGENTS.md`.

## Build, Lint, Test

### Commands

```bash
yarn install / yarn test / yarn depcheck                          # root
yarn client:start / client:run:ios / client:run:android / client:doctor
yarn client:typecheck / client:prebuild / client:check / client:build:unattended / client:e2e # client
yarn infra:start / infra:deploy / infra:remove                    # backend
yarn website:start / website:clean                                # website
yarn screenshots                                                  # screenshots
yarn workspace @ambito-dolar/website run build|preview
```

### Lint

- From repo root: `yarn eslint packages`, or scoped `yarn eslint "packages/<ws>/<path>"`.
- Before handing work back run root `yarn test`.
- **`eslint`, `prettier`, `tsc` and `ava` are root devDependencies, they resolve from the repo root only.** A workspace sees only what it declares, so calling them elsewhere, `cd` into a workspace inside the same command included, answers `Couldn't find a script named "eslint"`. Inside a workspace use `yarn run -T <binary>`. Typecheck the client with `yarn client:typecheck` from the root.

### Tests

- Root `yarn test` lints every workspace and runs the AVA tests of `packages/core`, `packages/backend` and `packages/client` through lerna. CI runs it on every push. Website and screenshots have no test script. Details in each package `AGENTS.md`.
- `yarn client:e2e` builds when needed and runs the client argent e2e tests on the iPhone 18 Pro Max simulator, then an emulator, local only, never in CI. See `packages/client/AGENTS.md`.

## Code Style

### Formatting

- Prettier and EditorConfig read their own config. Root `yarn test` does not check formatting, run `yarn prettier --write` on the files you touched.
- Match nearby style before broad reformat.
- Comments: lowercase default, keep existing uppercase unless editing that line. Terse, ASCII-only, no arrows/em-dash/checkmarks/special chars. No trailing period. One sentence per `//`, one line where it fits. Multi-line only for a second distinct fact, consecutive `//`, never prose-with-semicolons.
- No label-prefix comments (`// feature flag:`, `// android:`, `// <tag>:`). Plain sentence describing what or why.
- Contiguous related statements compact, no blank lines within decls/guards/memo/returns. Blank line only between distinct logical phases.

### Naming and modules

- Persisted keys, analytics events, API fields may be `snake_case`, keep stable.
- File naming mixed, match neighbors, no forced renames. New code in existing file when it fits, new file only when no natural home.
- JS-first (`.js`). Many config files CommonJS. No module-system conversions unless asked.

### Validation

- Validate at boundaries with `joi` or `yn`. Preserve public response shapes and the persisted storage schema.

## Git, commits, and releases

- **Commit and push directly to `master` by default.** That settles where, never when. Nothing is committed until the user calls the task closed or asks sooner; until then the work stays in the tree and the diff goes to them. One commit per closed piece of work, never one per edit. A change undone later in the same session never reaches the history. Branch or open a PR only when the user explicitly asks; the generic harness default "if on the default branch, branch first" does not apply here.
- Conventional commits (`@commitlint/config-conventional`). Types: `feat/fix/refactor/chore/docs/test`. No scope in subjects.
- Subject only, no body (body reserved for `BREAKING CHANGE:` footer). Preserve acronym/product casing (`CloudFront`, `S3`, `iOS`), never as the subject's first word.
- Subject names the real problem/effect, not the mechanism: `fix: unreadable android navigation bar in light mode`, not `fix: theme android navigation bar`.
- Preventive fix: `fix: prevent <effect>` (`fix: prevent expo-server-sdk v6 bundle break in notification lambdas`, `fix: externalize puppeteer-core to prevent social lambda crash`). Present tense (`X breaks`) only when the break actually happened.
- `chore: remove unused code` = pure removals only; refactors/restructures stay `refactor:`.
- Generic chore subjects (no per-file detail): `chore: bump build number` / `bump version and build number` / `bump yarn` / `bump dependencies`. `docs: update AGENTS rules`.
- Focused reversible commits, separate by type. No mixing unrelated packages. No experimental or temporary changes.
- Fewest commits the rules allow: same type and one concern merge into one, however many files. Only the type blocks a merge, never the count.
- No commit leaves the tree broken on its own. A manifest travels with its lockfile, a setting with the script it replaces, even dragging an unrelated hunk of the same file. A file carrying two concerns goes whole to the commit of the dominant one.
- Semver alignment across branch: major needs `BREAKING CHANGE:`, minor needs `feat:`, patch needs `fix:` only (no `feat:`).
- Lerna independent versioning, release from `master`.

Before any commit read `docs/commits.md`.

## Analytics and tracking policy

Open source, registered as not tracking user data beyond feature usage + ops problems. Default: no tracking.

- Coarse action names only. No properties/context that profile user (no productId, rate type, input value, timing).
- Sentry = error capture + breadcrumbs only, not an analytics channel.
- No new tracking without explicit user-visible reason in issue/PR. When in doubt, omit.

## Rate rollout gating

A new rate in development before the stores approve the client release is gated on the backend,
the client and the version check, or socials publish it before anyone can render it. See
`docs/product-policies.md`.

## Where the rates payload is served from

The URI the app reads is an env var, what it points at is a settled decision. Never change it as an
optimization. Cadence contract in `docs/product-policies.md`.

## Notification body and social caption

`getBodyMessage` feeds the push body and the social caption. Hard cap 300 characters; over it
reddit answers `NO_TEXT: title required`, which reads like something else. Simulate the caption
with every active rate before adding one. See `docs/product-policies.md`.

## Widgets

Written twice: native android in `packages/client/modules/widgets/`, SwiftUI on ios in
`packages/client/targets/RateWidgets/` and `packages/client/targets/_shared/`. A rate, market,
label, font size or `/fetch` schema change moves on both sides. The Apple Watch app in
`packages/client/targets/RateWatch/` shares the rate and market lists and the `/fetch` reading with
the ios widget through `packages/client/targets/_shared/`.

Four things outside the widget files break them when moved:
`packages/client/assets/fonts/FiraGO-Regular.otf`, the build `API_URL` env var (the CloudFront
alias that caches `/fetch`, never the raw API Gateway url), the `ambito-dolar` scheme with its
`/rates[/type]` and `/markets[/type]` routes, and the app `AppTheme`. Only the font and `API_URL`
fail loud, and only on android, `API_URL` not on an unattended build.

Read `packages/client/docs/android-widgets.md` and `packages/client/docs/ios-widgets.md` before
touching any of that.

## Agent Operating Defaults

- No rename/move files unless task needs. Report what ran before handoff.
- A change to code a `.md` names updates that `.md` in the same commit.
- A behaviour preserving refactor is checked by running HEAD and the new code on the same inputs,
  `null`, empty and a failing read included.

### Reading and writing these files

Write them like the code comments: the fact, not the narration. Drop connectives, keep every
identifier, number and device name. Every word here is paid on every session that loads it.

Rules live at three levels: this file, `packages/<name>/AGENTS.md` and `docs/`. Who could break a
rule decides where it goes. Read `docs/agents-doc-layout.md` before adding or moving a rule.

The repo is public: no `.md` carries billing, usage volumes, user counts, revenue, alarm thresholds
or an attack surface analysis, sanitized versions included. A stripped attack analysis still leaves
the map; a published alarm threshold says how much someone can burn before anyone notices. That
material lives outside the repo. What gets committed is the rule that keeps someone from breaking
something, standing on its own: a pointer from here to a private file is worse than no rule.
Product behaviour, public catalog prices and thresholds the code already carries are fine, as in
`docs/product-policies.md`.
